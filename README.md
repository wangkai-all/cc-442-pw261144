# 多来源采集调度器 (multi-source collector scheduler)

零依赖 Node.js(>=18)实现的多来源采集调度器:每个来源有独立的配额、优先级、
冷却时间和失败退避策略;内置公平性保底、崩溃恢复和幂等提交;附带实时监控页面
和基于模拟时钟的确定性测试。

## 快速开始

```bash
npm start          # http://localhost:3847 (PORT 环境变量可改)
npm test           # node --test,全部使用模拟时钟,秒级完成
```

首次启动会播种三个演示来源:`alpha`(高优先级但不稳定,55% 失败率)、
`beta`、`gamma`。状态快照写入 `data/scheduler-state.json`(每次状态变更时原子写入),
杀掉进程再重启即可看到配额消耗、退避状态和队列被恢复,在途任务以
`requeued-after-restart` 标记重新入队。

## 核心机制

### 来源配置(`registerSource`)

| 字段 | 含义 | 默认 |
|---|---|---|
| `priority` | 优先级,溢出槽位按它分配 | 0 |
| `quota` | 令牌桶 `{capacity, refillMs}`,每次派发消耗 1 个令牌 | 10 / 60s |
| `cooldownMs` | 同一来源两次派发的最小间隔 | 1000 |
| `maxConcurrency` | 来源级并发上限 | 1 |
| `minShare` | 公平性保底:为该来源预留的全局并发槽位数 | 1 |
| `backoff` | `{baseMs, factor, maxMs}`,连续失败 n 次暂停 `base*factor^(n-1)`(封顶 max) | 1s ×2, 封顶 60s |
| `demo` | 演示 worker 的 `{minMs, maxMs, failureRate}` | — |

### 公平性:保底 + 预留

调度分两步:

1. **保底优先**:低于 `minShare` 在途数的来源优先派发(等待最久的任务先走);
2. **预留约束**:已达到保底数的来源,只有当 `当前全局在途 < 全局上限 − 其他来源 minShare 之和`
   时才能溢出占用空槽——也就是说每个来源的保底槽位**永远不被别人抢占**。

因此高优先级来源无论是疯狂灌水还是持续失败(失败还会触发退避让出执行权),
其他来源都能获得最小执行机会;而低优先级来源没有需求时,空出的容量照常可被
高优先级来源使用(见 `test/fairness.test.js` 三个用例)。

### 配额与幂等

- 令牌只在**派发时**扣除,提交不扣;
- 任务 ID 是幂等键:重复提交(无论任务在排队、运行还是最近已结束)直接返回
  原任务,**不会重复扣配额**;已取消的 ID 可以重新提交;
- 取消运行中的任务会**退回**该令牌(抓取被中止,视为未消耗远端配额),且不计入失败;
- 取消排队中的任务不涉及配额(尚未消耗)。

### 失败退避与恢复

连续失败使来源进入退避(指数增长、封顶),期间该来源不可调度;任意一次成功
立即清零失败计数并解除退避。退避状态(`consecutiveFailures`、`backoffUntil`)
持久化,重启后继续生效。

### 持久化与崩溃恢复

每次状态变更(提交/派发/完成/取消)都会把完整快照原子写入(tmp + rename)
JSON 文件:来源配置与动态状态(令牌数、最近补充时间、失败计数、退避截止)、
队列、在途任务、最近结束任务(用于幂等去重)、事件日志。重启时:

- 配额消耗原样恢复(令牌按真实流逝时间继续补充,不会重置回满);
- 退避剩余时间继续生效;
- 快照时在途的任务以 `recovered: requeued-after-restart` 重新入队;
- 幂等去重集合保留,重启后重复提交仍被拦截。

## HTTP API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 监控页面(队列、配额、退避、取消恢复状态、事件日志,1s 自动刷新) |
| GET | `/api/state` | 完整状态 JSON |
| POST | `/api/sources` | 注册/更新来源(传完整配置;同 id 更新不影响动态状态) |
| POST | `/api/tasks` | 提交任务 `{sourceId, id?, payload?, count?}`,返回提交/去重计数 |
| POST | `/api/tasks/:id/cancel` | 取消任务(运行中取消退回配额) |
| POST | `/api/reset` | 清空状态并重新播种演示来源 |

## 代码结构

```
src/clock.js      时钟抽象:SystemClock / SimulatedClock(测试用,可手动推进)
src/scheduler.js  调度器核心(配额、公平性、冷却、退避、幂等、持久化)
src/store.js      JSON 快照存储(原子写)
src/worker.js     演示用模拟抓取 worker(按来源 demo 配置随机耗时/失败)
src/server.js     HTTP API + 静态页面
public/index.html 监控仪表盘(无框架,暗色主题)
test/             node:test + SimulatedClock 的确定性测试
```

## 测试覆盖(模拟时钟,20 个用例)

- **公平性**:高优先级来源持续失败/灌水时,低优先级来源仍获得保底执行;
  无需求时高优先级来源可以使用空闲容量
- **并发上限**:全局上限与来源级上限都不可突破
- **退避**:指数增长(1s→2s→4s→封顶)、退避期间不可调度、成功后立即恢复
- **配额与冷却**:令牌桶耗尽即停、按速率补充、冷却间隔精确生效
- **持久化**:重启后配额消耗/退避/队列恢复,在途任务重新入队,损坏快照安全降级
- **幂等**:重复提交不重复扣配额,取消后的 ID 可重新提交
- **取消**:运行中取消退回配额且不计失败,排队取消不动配额,释放的槽位立即被复用
